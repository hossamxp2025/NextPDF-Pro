# أدلة طبقة النص العربي (الإصدار 1.3.0، 2026-11-16)

السكربتات هنا هي التي بُنيت عليها قرارات `docs/internal/CLAUDE_IMPLEMENTATION_REPORT.md`.
تُشغَّل من جذر المشروع بـ `.venv\Scripts\python.exe -X utf8 <script> [outdir]`
وتطبع ما تقيسه؛ لا تعدّل شيئًا في المشروع.

| الملف | ماذا يقيس |
|---|---|
| `probe_fonts.py` | إدراج نص عربي بكل عائلة خط متاحة ثم إعادة الاستخراج والبحث. أساس قرار استبعاد Amiri وNoto Naskh. |
| `probe_variants.py` | 16 صيغة نصية (تشكيل، ربطات، bidi مختلط، أشكال عرض) لكل عائلة، ومقارنة المستخرج بالأصل بعد NFKC. |
| `probe_dedupe2.py` | يُظهر أن `xref_set_key` في PyMuPDF 2.1 يكتب `fitz: replace me!` بدل المرجع، وهو سبب إلغاء دمج الخطوط. |
| `probe_subset.py` | حجم الملف وعدد الخطوط ونتائج البحث قبل وبعد `subset_fonts()`. |
| `probe_align.py` | موضع الحروف داخل صندوق Story لكل قيمة محاذاة واتجاه. أساس اكتشاف عكس `text-align` تحت RTL والإزاحة الرأسية. |
| `probe_anchor.py` | الانحراف بين نقطة النقر وموضع الحبر بعد الإصلاح، للإضافة والاستبدال بثلاثة أطوال. |

## الصور

## نتائج مرجعية (من آخر تشغيل)

```
probe_align.py
rtl align=right  glyphs x[100.00,266.80]  box x[100.0,500.0]   <- انقلبت للحافة اليسرى
rtl align=left   glyphs x[333.20,500.00]  box x[100.0,500.0]   <- الحافة اليمنى فعليًا
rtl top_pad=-6.29   ltr top_pad=-2.02                          <- تجاوز الحروف فوق الصندوق

probe_subset.py
plain:  size=694623  fonts=6  hits={'المبلغ': 6, 'English': 1, 'عربي': 4, ...}
subset: size=124399  fonts=6  hits={'المبلغ': 6, 'English': 1, 'عربي': 4, ...}

probe_anchor.py
add rtl: dx=+0.00  dy=-0.00
replace: dx1=+0.00 dy0=+0.00   search 18,500: 1   old 15,750: 0
```
